# 网页产品分析报告：preview/index.html

| 项目 | 内容 |
|------|------|
| 页面 URL | `file:///Users/ycjcx123/Harmony_Practices2/HarmonyOS-METASERVICE-airport-guide/preview/index.html` |
| 分析日期 | 2026-09-28 |
| 页面定位 | 机场导航元服务的节点图数据可视化预览页（SVG 静态预览，非应用运行截图） |
| 技术实现 | 纯 HTML + `<object>` 标签引用 7 个 SVG 文件，无 JavaScript / 无 CSS 框架 |

> 本报告从产品经理视角对 preview/index.html 进行七维度分析。该页面为开发者工具型页面（数据可视化预览），非面向终端用户的产品页面，分析视角相应调整为「开发者使用者体验」。

---

## 一、首屏价值与体验

### P1-1：页面缺少定位说明，首屏无法判断页面用途

- **现象**：页面标题为「机场节点图预览」，H1 为「机场导航元服务 · 节点图预览」，H2 为「星海国际机场 主航站楼」。但首屏直接展示 4F 出发层的 SVG 图，无任何说明文字解释这些图是什么、怎么看、与实际应用的关系。
- **影响**：开发者打开页面后无法快速判断这是「数据拓扑图」「应用截图」还是「设计稿」。需要滚动查看全部 7 张图后才能理解。
- **建议**：在 H1 下方加一段说明文字，如「以下为 data/XHA_xinghai_t1.map.json 的 SVG 可视化预览，由 tools/preview_nodes.py 生成，用于开发期校验节点位置与边连接关系。非应用运行截图。」

### P2-1：首屏信息密度低，单张 SVG 占满视口

- **现象**：每个 `<object>` 标签 `width="100%"`，单张 SVG 占满整个视口宽度，7 张图纵向排列导致页面极长。首屏只能看到 4F 一张图的上半部分。
- **影响**：开发者需大量滚动才能浏览全部楼层，对比不同楼层时需来回滚动。
- **建议**：可将 SVG 缩小为 2 列网格布局（如 4F/3F 一行、2F/1F 一行、B1/B2 一行），或增加楼层快捷导航锚点。

---

## 二、信息架构与导航

### P1-2：无楼层快捷导航，7 层纵向排列无锚点

- **现象**：页面有 7 个 `<figure>`（4F / 3F / 2F / 1F / B1 / B2 / 全览），纯纵向排列，无导航栏、无锚点跳转、无楼层筛选。
- **影响**：开发者想查看特定楼层（如 B2 地铁站台）时需滚动到底部。6 层楼层的顺序虽按 4F→B2 排列（与实际楼层一致），但缺少快捷入口。
- **建议**：在页面顶部加一组楼层锚点链接（4F | 3F | 2F | 1F | B1 | B2 | 全览），点击跳转到对应 figure。

### P2-2：`figcaption` 信息过于简略

- **现象**：每个图的 `figcaption` 只有楼层名（如「4F 出发层」「B2 地铁站台」），无节点数、边数、包围盒等数据摘要。
- **影响**：开发者无法从预览页快速获取各楼层的数据规模信息。
- **建议**：在 figcaption 中补充节点/边数量，如「4F 出发层（38 节点 / 42 边）」。

---

## 三、内容策略

### P2-3：全览图（overview）放在最后，重要性排序合理

- **现象**：全览图作为最后一个 figure 展示，排在 6 层之后。
- **影响**：全览图是总览性质的图，放在最后作为汇总查看是合理的安排。
- **建议**：保持现状。

### P2-4：SVG 图内容为程序生成，无人工标注

- **现象**：7 个 SVG 文件由 `tools/preview_nodes.py` 自动生成，包含节点圆点、边连线、节点标签，但无图例、无比例尺、无安检高亮标注。
- **影响**：开发者查看 SVG 时无法区分节点类型（登机口/安检/电梯等颜色含义需对照 Theme.ets 的 TYPE_COLOR），也无法直观看到安检必经路径。
- **建议**：在 SVG 中增加图例面板（节点类型色 + 名称），或在 HTML 页面中增加一个图例说明区。

---

## 四、用户路径与转化

### P2-5：页面无操作引导，纯展示型

- **现象**：页面为纯展示型（view-only），无交互按钮、无搜索、无筛选。开发者的唯一操作是滚动浏览。
- **影响**：作为数据可视化预览工具，纯展示是可以接受的，但缺少「如何生成这些图」的引导。
- **建议**：在页面底部或顶部加一行「运行 `python3 tools/preview_nodes.py` 重新生成」的提示，方便开发者更新预览。

### P2-6：无返回项目主页的链接

- **现象**：页面无返回 README 或项目根目录的链接。
- **影响**：开发者从 preview/index.html 进入后，无法直接跳转到项目文档或源码。
- **建议**：在页面顶部加一个返回链接，如 `<a href="../README.md">← 返回项目说明</a>`。

---

## 五、交互与易读性

### P2-7：页面无响应式适配

- **现象**：页面 CSS 只有 `body{margin:24px}` 和 `svg{max-width:100%}`，无 `@media` 查询、无移动端适配。
- **影响**：在窄屏设备上 SVG 会缩放到很小，节点标签可能不可读。但此页面主要面向桌面端开发者使用，影响有限。
- **建议**：低优先级。可增加 `@media (max-width: 768px)` 下的网格列数调整。

### P2-8：字体使用系统默认，跨平台一致性可接受

- **现象**：CSS `font-family: system-ui, -apple-system, 'PingFang SC', 'Microsoft YaHei', sans-serif`。
- **影响**：跨平台字体回退合理，中文显示正常。
- **建议**：保持现状。

### P2-9：SVG 边框样式简洁清晰

- **现象**：SVG 有 `border:1px solid #e1e0d9; border-radius:8px`，视觉上轻量整洁。
- **影响**：无问题，样式得体。
- **建议**：保持现状。

## 六、安全与信任

### P2-10：无敏感信息暴露

- **现象**：页面为纯静态 HTML + SVG，无后端、无 API、无用户数据、无 Cookie。
- **影响**：无安全问题。
- **建议**：不适用。

### P2-11：无版权/备案信息

- **现象**：页面无 copyright、无许可证声明、无维护者信息。
- **影响**：作为内部开发工具页面影响极低。项目根目录有 MIT LICENSE。
- **建议**：低优先级。可在页面底部加「MIT License · harmony-practice-center」。

## 七、技术与性能

### P2-12：使用 `<object>` 而非 `<img>` 引用 SVG，支持交互但增加复杂度

- **现象**：页面用 `<object data="XHA.4F.nodes.svg" type="image/svg+xml">` 引用 SVG，并提供了 `<img>` 回退。
- **影响**：`<object>` 方式允许 SVG 内部交互（如 hover/zoom），但也意味着 SVG 的渲染独立性更高，样式继承更少。当前 SVG 无交互需求，用 `<img>` 更简单。
- **建议**：可简化为 `<img>` 标签，减少 DOM 复杂度。但当前方案有回退机制，功能完整，不改也无妨。

### P2-13：7 个 SVG 文件总体积小，加载快

- **现象**：preview 目录下 7 个 SVG 文件均为程序生成的矢量图，体积小（每个几 KB 到几十 KB），页面加载几乎瞬间完成。
- **影响**：无性能问题。
- **建议**：保持现状。

### P2-14：无 JavaScript 依赖，纯静态页面

- **现象**：页面无任何 JavaScript，纯 HTML + CSS + SVG。
- **影响**：无兼容性问题，无运行时错误风险。
- **建议**：保持现状。

---

## PortalUI 适用性判定

### PortalUI 不适用

- **判定**：**PortalUI 不适用**
- **依据**：preview/index.html 是一个**内部开发工具页面**（数据可视化预览），用于开发期校验节点图拓扑。它不是华为云门户网页、不是 PEP 页面、不是 cui 套件页面，不涉及任何门户组件（por-btn / por-modal / por-carousel / por-select 等）场景。页面仅需展示 SVG 图，无表单、无弹窗、无轮播、无选择器等门户组件需求。强行引入 PortalUI 不仅无益，反而增加不必要的依赖和复杂度。
- **建议**：保持纯 HTML + SVG 的轻量实现，不引入任何 UI 组件库。

## 产品定位小结

preview/index.html 是一个**功能最小化的内部开发工具页面**，核心价值是让开发者在浏览器中快速查看地图数据的 SVG 可视化结果。页面技术实现简洁（纯 HTML + SVG，零依赖），加载性能优秀。主要短板在于**缺少定位说明和导航锚点**——开发者打开后需要自行理解页面用途和滚动浏览全部楼层。

核心优化方向：
1. 在页面顶部增加定位说明文字（P1-1），一句话说明这是数据可视化预览
2. 增加楼层快捷导航锚点（P1-2），提升多楼层浏览效率

> PortalUI 不适用：此页面为内部开发工具，非门户网页，不涉及任何 PortalUI 组件场景。
