## 0. 结论先行（一页给领导看）

打开元服务，就是一个**真实可逛、能帮你把路走通**的机场导览：

- 六层航站楼（4F 出发 → B2 地铁站台）随手切换，每层一张示意图，节点标得明明白白；
- 想找登机口 B203、想坐地铁去市区、想知道行李在哪取——**分类浏览 + 搜索**直达目标；
- 选好起点（某个门 / 地铁站台 / 任意节点）→ **跨层最短路**自动算出来，图上**逐层画出路线**，换层该坐电梯还是扶梯讲得清清楚楚；
- 去登机口必然路过**中央安检大厅**——路线把安检标注出来，**绝不会绕过安检**（呼应"唯一安检是陆侧↔空侧咽喉"的结构约束）；
- 地下两层单独有**地铁换乘引导**：往市区还是往星湖度假区，哪个站台、怎么下去，一目了然；
- 中英双语切换，路径是**画出来的动效**，跟着走就行。

四要求对照：

| 要求 | 本作回答 |
|---|---|
| **有趣** | 打开即真实机场，六层示意图 + 可逛节点，信息丰满、动手可走 |
| **做下去** | 完整导航闭环：选目标→选起点→跨层寻路→逐层路径图→换乘说明，是"能走通"的产品不是效果 |
| **留住** | 一次设一条常用路线可快速重看；双语+地铁引导覆盖机场最常问的两件事"去哪登机""怎么坐地铁" |
| **学习** | 每个形态对应鸿蒙知识点：Dijkstra 落地 ArkTS、Canvas 拓扑图绘制、Navigation 多页、资源双语、动效与转场 |

## 1. 用户与场景

**目标用户**：机场出发旅客、到达接机人、地面换乘旅客。面向"站在机场里要赶路"的人。

**典型场景**（都发生在开机 30 秒内）：

1. **出发场景**：从西出发门进来，要去登机口 C308 → 搜"登机口"选 C308 → 起点选"西出发门" → 路线：值机区 → 中央安检大厅（必经，标注）→ 空侧免税商业区 → C 指廊 → 登机口；换层时提示乘空侧电梯/扶梯下 3F 或沿 4F。
2. **到达/接机场景**：下飞机在 2F 到达 → 问"行李在哪取""怎么出去坐网约车"。搜"行李提取"→ 定位 2F A/B 区；点"出租·网约上车点"→ 路线到 1F。
3. **地铁换乘**：要去市区 → 搜"地铁"→ 选"站台·往市区方向"→ 路线：B1 地铁闸机群 → 地铁扶梯/楼梯 → B2 站台·往市区方向。
4. **地面浏览**：不确定去哪 → 首页各楼层随便逛，点节点看"这在哪层、什么功能"。

**边界（明确不做）**：无实时航班/登机口变更（静态示意数据，将来替换 gate 坐标即可接动态数据）；无室内定位（"起点"由用户选择，模拟当前位置）；无账号/云端/支付。

## 2. 首版功能范围

### 2.1 首页：机场总览与楼层导航

- 机场标识（星海国际机场 XHA · 主航站楼）、楼层快速入口（6 层，名称+当前层状态）；
- 主功能区入口：**分类/搜索**、**地铁换乘引导**、**双语切换**；
- 展示"当前楼层"缩略图（示意），点击进对应楼层图。

### 2.2 目标（终点）选择：分类浏览 + 搜索

按语义把 119 个节点归成用户可理解的类目（映射表见 §4）：

| 类目 | 覆盖节点类型 |
|---|---|
| 登机口 | `gate`（24 个，A/B/C 指廊） |
| 值机与安检 | `checkin`（4 岛）、`security`（唯一中央安检大厅） |
| 出入口 | `entrance`（西/北/东出发门）、`exit`（到达出口×3） |
| 行李 | `baggage`（行李提取 A/B）、`corridor` 行李寄存处 |
| 地铁 | `metro`（B2 双向站台）、`metro` 相关站厅/闸机（B1） |
| 交通接驳 | `coach`（出租网约、大巴、B1 候车区） |
| 停车与地面 | `parking`（P1 停车楼）、1F 迎客大厅/连廊 |
| 商业与服务 | `hall`（空侧免税、餐饮、贵宾室A/B、亲子区、各层大厅/夹层）、`toilet` |
| 换层设施 | `lift`/`escalator`/`stair`（19 电梯 / 7 扶梯 / 7 楼梯） |

- 搜索：按名称（中英文关键词均可命中，如"地铁""metro""B203""安检"）；
- 结果即点即选为目标终点。

### 2.3 起点选择

- **快捷起点**（模拟当前位置）：西/北/东出发门、主到达出口、地铁站台（往市区/星湖）、1F 出租网约上车点、B1 交通中心大厅；
- **任意节点**：跨层换乘设施、登机口等也可作为起点；
- 默认起点 = 最近一次选过的起点（会话内记忆）。

### 2.4 寻路引擎：跨层最短路 + 安检必经

- **算法**：Dijkstra，边权 = `walk`（米，已在数据里算好）/ `elevator` 30 / `escalator` 40 / `stair` 25；
- **跨层**：节点图含 21 条垂直边（3 空侧电梯 + 10 公共电梯共享井道 + 4 扶梯 + 4 楼梯），寻路天然支持"跨两层或跨多层"；
- **安检必经（核心约束）**：XHA 图中唯一中央安检大厅是陆侧↔空侧的**割点（唯一通路）**。寻路规则：
  - 起点与终点**分属两侧**（陆侧：门/值机/到达/地铁/接驳/地面；空侧：登机口/空侧商圈/3F 夹层/观景台/贵宾室/亲子）→ 路径**强制拆段**：`起点 → 中央安检大厅 → 终点`，两段 Dijkstra 拼接，安检作为**必经节点醒目标注**；
  - 起点与终点**同侧** → 直接 Dijkstra，不走无意义的安检折返；
  - 此约束由数据结构保证（唯一安检即咽喉），端侧用"必经点拆段"实现，寻路**不可能略过安检**；
- 换层偏好：默认按最短权重；UI 提供"优先电梯 / 优先扶梯 / 避开楼梯"三种偏好（调整垂直边权重后重算）。

### 2.5 逐层路径图（导航主画面）

- 每层渲染：**手绘示意图背景**（轮廓/指廊/区块，见 §5）+ **拓扑节点/连线** + **路径高亮** + 比例尺标尺；
- 跨层路线：自动按经过楼层生成**逐层分页**，每页显示该层的路径段与"你在哪→去哪"；
- 换层节点（电梯/扶梯/楼梯）单独提示：如"乘中庭观光电梯到 1F"；
- 路径**绘制动效**：选中后路径逐段描画（约 0.6~1s），换层跳转有转场；
- 每层信息条：楼层名 + 该层路径长度 + 累计距离。

### 2.6 地铁换乘引导（专项流程）

- 从"搜地铁 / 首页地铁入口"进入：先选方向（**往市区** / **往星湖度假区**）→ 引导页：
  1. 到 B1 **地铁闸机群**（当前层若在其他楼层，先画跨层路线）；
  2. 过闸机 → 地铁扶梯（或楼梯）**下 B2**；
  3. 到对应**站台**（站台·往市区方向 / 站台·往星湖度假区），显示候车提示。
- 复用同一寻路引擎，仅以"地铁站厅→闸机→站台"为内置目标链。

### 2.7 中英双语

- 全部界面文案走 `$r('app.string.*')`，`resources/base`（中文）+ `resources/en_US`（英文）双目录；
- 右上角开关即时切换，切后整页文案与节点标签即时刷新；
- 节点 name 双语：数据为中文，英文为映射表译文（不认识的节点名回落中文/原样）。

### 2.8 寻路动效与转场

- 路径逐段描画动画（Canvas 按进度 paint）；
- 楼层切换翻页转场（Navigation + 页面过渡）；
- 目标/起点选择用 `bindSheet` 半模态，轻量不跳页。

## 5. 地图呈现方案（手绘示意图背景 + 拓扑叠加）

- **示意背景**：每层独立"图片来源坐标系"（与数据同一套坐标，天然对齐）。背景内容 = 楼体轮廓、指廊通道面板、功能区块色带、轻网格与比例尺——体现"示意图"观感；
- **实现路径**：首版背景由 ArkTS **程序化绘制**（几何造型层先画，节点拓扑层后叠），避免把二进制约位图塞进仓库/版本管理；同时预留 `drawImage` 插槽，将来若有手工位图可无缝替换背景层；
- **拓扑层**：节点圆 + 类型色 + 双语标签；walk 边细线、垂直边虚线分色（与 `preview_nodes.py` 图例一致）；
- **路径层**：高亮段（粗色线）+ 必经点（安检）醒目标记 + 起终点图标；
- 渲染统一视口变换：平移/缩放同一矩阵作用于背景与拓扑，保证对齐。

## 7. 验收清单

### 业务验收（领导走查）

1. 打开即机场总览，六层可入；
2. 搜"登机口 C308"→ 选择 → 起点选择 → 出路线，逐层有图、有路径；
3. **陆侧→空侧路线必经中央安检大厅**（路径明确标注，无法绕过）；
4. 空侧→陆侧（如从登机口去地铁）同样经安检，方向合理；
5. 同侧两点（两个登机口之间）路线不再折返安检；
6. 换层有提示（坐哪部电梯/扶梯），换层距离计入总里程；
7. "地铁·往市区/往星湖度假区"流程能到 B2 对应站台；
8. 中英开关一切即换，节点名同步；
9. 路径为动效绘制，页面切换平滑。

### 技术检查（对照 README 模板 §5）

- 工程为 atomicService 元服务，真机/模拟器可装可跑；
- 无任何账号/云服务/支付依赖；无硬编码用户文案；
- 数据与 `data/XHA_xinghai_t1.map.json` 逐字段一致（同源校验）；
- 寻路正确性自测：随机 500 对（起点,终点）与 Python 端参照实现结果一致（含安检必经断言）。

## 8. 风险与开放问题

| 项 | 影响 | 处置 |
|---|---|---|
| 示意图背景的"好看程度" | 首版为几何示意 | 先跑通再迭代配色/细节，插槽允许换位图 |

| 图标资源 | 无现成图标 | 用 ArkTS 绘制符号/Emoji 兜底，不引外部包 |
