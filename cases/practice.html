实践步骤

本案例采用对话式开发（AI 编程工具 + 人工确认需求），以下是完整开发流程的关键步骤，按时间顺序排列。你可以直接复制每条指令发给 AI，逐步完成。

步骤 1：生成需求文档

  1. 向 AI 提出需求：告知 AI 要做一个鸿蒙 App——机场室内地图导航（星海国际机场，虚构机场 XHA），让 AI 通过提问确认需求细节（覆盖楼层、寻路偏好、安检限制、双语范围、地铁换乘引导、界面风格）。
  2. 确认需求要点：六层航站楼（4F→B2）、地图数据随包纯本地、完整导航闭环（分类/搜索选终点→选起点→跨层最短路→逐层路径图）、中央安检必经且醒目标注、换层偏好四档、中英双语即时切换、地铁换乘引导、路径绘制动效。
  3. 产出：需求规格文档，含功能需求、验收标准、UI 设计要求和数据约定。参见 docs/需求文档.md。

完成标志：需求文档包含六层总览、分类+搜索、跨层寻路、安检必经、逐层路径图、地铁引导、中英双语、路径动效等功能定义。

步骤 2：生成架构设计

  1. 向 AI 发送：根据该需求文档生成一份架构设计。
  2. 关键设计决策：pages → core → model → ui 的分层结构；Dijkstra 寻路 + 安检必经拆段；Canvas 三层渲染（示意背景/拓扑/路径）；数据管道 JSON → 类型化模型编译进包；Navigation 多页面 + NavDestination 分发。
  3. 产出：架构设计文档，含分层架构图、模块职责、数据流、技术选型。参见 docs/开发文档.md。

完成标志：架构文档包含分层结构图、寻路算法方案（含安检拆段逻辑）、渲染方案（Canvas 三层 + 视口变换）、数据同步链。

步骤 3：生成完整应用代码

  1. 向 AI 发送：根据需求文档和设计文档生成App。
  2. 工程结构：harmony_app/ 目录下包含 entry 模块（AppScope/entry）、6 个页面（pages/）、3 个核心模块（core/）、2 个 UI 组件（ui/）、4 个模型文件（model/）、资源文件（resources/）。
  3. 数据管道：先编写 data/XHA_xinghai_t1.map.json（119 节点 / 145 边 / 6 层），再用 tools/gen_model.py 编译生成 model/AirportMap.ets（类型化常量，含 side 陆空侧 BFS 分类、NODE_EN 英文翻译、FLOOR_BBOX 包围盒）。
  4. 寻路引擎：core/Pathfinder.ets 实现 Dijkstra（朴素法，119 节点规模足够），垂直边权重电梯30/扶梯40/楼梯25，偏好乘子四档。安检必经拆段：异侧起终点拆成 起→安检→终 两段拼接。
  5. 渲染：ui/FloorCanvas.ets Canvas 单层绘制三层内容（示意背景 + 拓扑 + 路径），共用 core/Viewport.ets 视口变换。路径动效用 setInterval(16ms) 驱动 progress += 0.02。

完成标志：工程可通过 hvigorw assembleHap 编译通过，生成 HAP 安装包。

步骤 4：运行到模拟器并验证

  1. 编译：设置环境变量（DEVECO_SDK_HOME / JAVA_HOME / NODE_HOME / PATH），在 harmony_app/ 下执行 hvigorw assembleHap --no-daemon --mode module -p product=default -p module=entry@default。
  2. 安装：启动 API 23+ 模拟器，hdc -t 127.0.0.1:5555 install -r entry/build/default/outputs/default/entry-default-unsigned.hap。
  3. 启动：hdc shell aa start -a EntryAbility -b com.example.airportguide。
  4. 验证：依次验证六层总览、分类搜索（搜「登机口 C308」）、跨层寻路（异侧必经安检）、逐层路径图、地铁引导、中英切换、路径动效。

完成标志：应用正常运行，所有验收项通过。

步骤 5：修复问题与迭代优化

验证过程中发现的问题及修复方案：

问题（用户可见）根因修复方案
四种偏好下距离显示不一致 planRoute 选路用偏好乘子，显示距离也用了乘子后的权重 选路用偏好乘子、显示距离一律用数据原始权重（walk=真实米，垂直=基准 30/40/25），偏好只影响选路不改显示距离
直达路线残留 3F/2F 空 Tab 跨层路线中间楼层只有单节点过站（电梯停站），生成了空楼层分页 mergeTransitLegs 把单节点过站腿吸收为一条直达换乘，Tabs 只含真实途经楼层
FloorBrowse 弹窗大片白区 bindSheet 弹层未设置 backgroundColor，默认白底 bindSheet 选项加 backgroundColor: APP.bg（弹层深色无白区）
出发点不明 + 缺地图式 UI SelectTarget 顶栏无起点显示，FloorBrowse 无设为出发点/目的地入口 SelectTarget 顶栏加「起点|交换|终点|确认」；FloorBrowse 节点弹层加「设为出发点/设为目的地/取消」

完成标志：所有问题修复，重新构建安装到模拟器后功能正常，视觉效果明显改善。

验证方法

  1. 编译验证：hvigorw assembleHap 全绿，产物 entry-default-unsigned.hap 生成。
  2. 数据一致性：python3 tools/gen_model.py 重跑幂等，diff 为空（AirportMap.ets 与 map.json 逐字段一致）。
  3. 寻路回归：python3 tools/pathfind_reference.py 跑 500 组随机用例与端侧 Pathfinder 比对，异侧 270 例全部含 xha_p4_sec，同侧 230 例全部不含。
  4. 模拟器实测：安装到 HarmonyOS 6.1.0(23) 模拟器，人工验证全部 9 项业务验收 + hilog 无 FATAL/JsError/CppCrash。
