## 案例概览

星海国际机场是**示例机场**，地图并非真实机场导览数据。项目是本地运行的 HarmonyOS <code>atomicService</code>，包名为 <code>com.example.airportguide</code>，应用版本为 <code>1.0.0</code>。地图随应用提供，无须云端、账号或 API 密钥；起点由用户手动指定，步骤也由用户手动确认，不能作为实时定位或现场导航使用。

地图源文件 [XHA_xinghai_t1.map.json](data/XHA_xinghai_t1.map.json) 包含 **6 层、119 个节点、145 条边**。并非每个图节点都进入地点搜索：通道节点主要用于寻路，只有公开地点和少数指定通道可供选择。<code>tools/gen_model.py</code> 读取图数据，并用脚本内的 <code>NAME_EN</code> 字典补齐英文名称，生成 ArkTS 模型供寻路和展示使用。原有 <code>planRoute(startId, endId, pref)</code> Dijkstra 接口保留；本例图谱规定陆侧与空侧之间的路线必须经过中央安检，不能绕行。

用户体验从**目的地 → 手动选择出发位置 → 路线预览 → 当前与下一步指引 → 逐项确认**展开。六个页面分别是首页、目的地选择、起点选择、路线、地铁方向和楼层地图。地铁页可选往市区或往星湖方向，地图页支持六层浏览和点位选择。

路线提供四种偏好：**推荐路线、优先电梯、优先扶梯、尽量少走楼梯**。偏好影响选路；页面中的“步行约”只累计步行边，电梯、扶梯或楼梯换层单独提示和计数。切换查看其他路段或楼层不会推进指引。修改偏好、确认编辑起终点或交换起终点会重新规划并从预览开始；取消编辑保留原路线及进度。语言和最多 6 个最近目的地保存在本机 preferences，正在进行的指引进度只在当前会话保存。

本案例可用于学习结构化地图数据、受约束寻路与多页面状态协作。若要接入真实机场，仍需取得授权地图及运营数据，并另行处理定位、数据更新、签名发布和现场验证。

### 本地：用码道 IDE 获取案例

准备[码道 IDE](https://support.huaweicloud.com/usermanual-codeartsagent/codeartsagent_ug_0002.html) 与 HarmonyOS Command Line Tools，或者已有可用的 DevEco Studio 工具链。按码道官方使用指导打开准备存放工程的文件夹，在对话框输入下面这段话，让 AI 拉取现成案例：

~~~text
请把这个公开案例仓库拉取到当前工作区：
https://gitcode.com/harmony-practice-center/HarmonyOS-AtomSer-airport-guide.git
先确认仓库可访问，不要覆盖我已有的文件。
拉取后检查是否包含 HarmonyOS 工程、地图数据和说明文件。
最后告诉我工程实际放在哪个目录、下一步应该打开哪个工程目录。
~~~

**完成标志：** 能看到案例工程及其 <code>harmony_app</code> 目录。若本地网络、Git 或访问权限导致失败，让 AI 报出实际错误并给出针对性的修复步骤，不要把未拉取成功当作工程已到位。

### 共用：解析工程并编译

云端或本地拿到案例工程后，在当前工作区输入：

~~~text
请识别当前工作区中 HarmonyOS 工程的实际根目录、元服务入口和可用的构建工具。
请用当前环境的 SDK、Node 和 Java 执行一次调试构建，产出 HAP。
遇到路径、依赖或编译错误时，根据具体日志做最小修复并重建。
不要擅自改动地图示例数据、寻路规则或包名。
最后报告实际构建命令、是否出现 BUILD SUCCESSFUL、HAP 完整路径和签名状态。
若未成功，请说明阻塞点，不要宣称已完成。
~~~

**完成标志：** 构建日志出现 <code>BUILD SUCCESSFUL</code>，并能找到实际 HAP 文件。这里不写死某台开发机的安装路径；若你想手动排查，可参考[早期构建笔记](docs/BUILD.md)，但本版证据和环境边界以[产品体验记录](docs/reports/ProductExperience-20261001.md)为准。

## 完整实践

这条路径是**从空白项目独立完成一版元服务**，不拉取或复制完整示例工程，也不要求 AI 阅读本仓库源码。云端从作业中心手工新建“空项目”，**案例仓地址留空**；本地在码道 IDE 打开一个空文件夹。第 2 步会让 AI 只下载**一份地图 JSON 和三张原始参考截图**到自己的 <code>reference/</code> 目录。四个地址固定到同一份已发布素材版本，用于教学复现；若网络不可用，可以手动仅下载这四份文件放入该目录，不能用网页 HTML 冒充 JSON、让 AI 编造节点，或改为克隆完整示例仓库。每阶段产出的需求、设计和验证记录保存在自己的工作区。

下面八组提示词可依次复制。每组都说明当前目标、预期操作和完成标志；从第二组起可以使用上一阶段**在自己工作区**产生的记录。让 AI 在每阶段控制修改范围、实际检查结果并修复问题，再进入下一阶段。[华为云的从空文件夹开发元服务示例](https://support.huaweicloud.com/bestpractice-codeartsagent/codeartsagent_bp_0050.html)可作为使用方式参考，但本案例的地图、交互与验收条件以下述提示词为准。

### 1. 检查环境

**目标：** 知道当前工作区、SDK、构建工具和设备是否就绪，不先生成业务代码。

**复制给 AI：**

~~~text
我要从当前空项目独立制作 HarmonyOS 机场导航元服务。
请先只读检查工作区是否为空、能否创建原生元服务工程、可用 SDK 和构建工具。
再检查云手机或模拟器状态，以及能否访问公开素材地址。
分清已确认事实、缺少的工具和需要我在界面完成的操作。
不要拉取完整案例仓库，不要安装未经我确认的大型工具，也不要先写业务代码。
~~~

**完成标志：** 得到一份环境清单，明确工具、设备和素材下载条件，并知道下一步应在哪里创建工程。

**完成标志：** <code>reference/</code> 只有这四份且格式正确的素材；六页、起终点流程、手动位置边界、安检和换层、双语与适配要求都有清楚的验收条件，设计记录不依赖本仓库源码。

### 3. 创建可编译的原生元服务工程

**目标：** 先得到最小可构建的原生工程与入口，避免业务功能和工程配置一起失控。

**复制给 AI：**

~~~text
请依据当前工作区刚保存的需求和设计记录，创建原生 HarmonyOS ArkTS 元服务工程。
设置适合当前工程的包名、应用入口、基本资源和六页空白导航骨架。
先识别可用 SDK 与构建工具，不写死其它机器的路径，也不要复制现成案例工程。
执行一次真实调试构建，按具体错误日志做最小修复。
请报告工程目录、入口、实际构建命令、HAP 位置和六页能否从首页进入。
若尚未连接设备，明确这次仅验证了代码或编译，没有验证界面运行。
~~~

**完成标志：** 构建成功、有 HAP 产物，六页骨架与入口可被检查；尚未接入地图时不宣称导航已完成。

### 4. 接入统一地图，做首页与目的地搜索

**目标：** 用给定的示例图数据驱动可选择地点，保持楼层、坐标和连通关系一致。

**复制给 AI：**

~~~text
请使用当前工作区 reference/map.json 和三张原始参考图，接入自己的元服务工程。
先完成首页、六层入口和目的地分类/搜索，不从截图猜测地图数据。
首页标题为“你想去哪里？”，有“去登机口”“坐地铁”“找设施”三个入口。

地图有 4F、3F、2F、1F、B1、B2 六层，119 个节点、145 条边。
关键 ID：xha_p4_sec 为中央安检，xha_p4_doorW 为西出发门，
xha_p4_airMall 为空侧商业区。节点有 id、中文 name、type、floor、坐标；
type 为 lift 的节点代表电梯。边有 from、to、type、weight。
walk 的 weight 是步行米数，垂直边 weight 是选路成本，不计入步行米数。
原 JSON 只有中文名，请独立建立用户可见地点的英文名称与登机口别名。
side 不是原 JSON 字段，要依据图谱与安检连接关系推导或另建可靠分区。

公开地点可分类和搜索，普通中转节点不要全暴露在列表。
搜索忽略首尾空格与英文大小写，精确登机口编号排在前面。
无结果时给出清除查询与重新选择的入口。
选好目的地后用“选择出发位置”继续；地铁入口先让用户选往市区或往星湖，
之后复用相同的手动起点选择流程。
后续起点页标题应为“你现在在哪里？”，选择起点后用
“从这里出发，查看路线”进入预览，再用“开始指引”进入人工步骤。
请检查实际字段和连通性，完成数据加载、搜索和首页，运行可行的检查。
记录未完成项；不要运行会覆盖素材 JSON 的重建脚本。
~~~

**完成标志：** 页面能看到六层和公开地点，A101 等登机口能搜索选择，普通中转节点不会全部出现在地点列表；数据仍可追溯到原始 JSON。

### 5. 完成起点与规划

**目标：** 实现从目的地到手动起点、可解释的路线预览。

**复制给 AI：**

~~~text
请完成“先目的地、后出发位置”的行程流程。
新行程起终点首次进入时都为空，起点由用户手动选择，不假装有室内定位。
起点页显示“你现在在哪里？”，选定后用“从这里出发，查看路线”进入预览。

根据已接入的图实现可复核的最短路规划。
提供“推荐路线、优先电梯、优先扶梯、尽量少走楼梯”四种偏好。
本例陆侧与空侧之间必须经过 xha_p4_sec 中央安检，同侧无需绕行。
预览分开显示步行米数和换层次数：步行只加 walk 边，
垂直边只影响选路并单独形成换层提示。预览有“开始指引”按钮。
请自测西出发门到 A101、同侧两点，以及跨层到地铁站台三类输入，
说明关键经过点。若无法连通，指出数据或实现中的具体原因。
~~~

**完成标志：** 从目的地和手动起点能得到预览；异侧经安检、同侧无需安检，跨层步骤与步行米数分离，错误或相同点位有明确反馈。

进入第 6 阶段前，如要做设备实测，云端先按[快速体验](#快速体验)中的平台流程创建云手机并等待运行、连接；本地按[模拟器创建说明](https://developer.huawei.com/consumer/cn/doc/HarmonyOS-Guides/ide-emulator-create)启动模拟器。若暂时没有设备，可继续代码与逻辑检查，但须明确记录“设备未测”，并在第 8 阶段补做实际安装与操作。

### 6. 完成地图与手动指引

**目标：** 让路线能在地图上看见、按步骤实际操作。

**复制给 AI：**

~~~text
请在现有路线基础上完成六层示意地图和预览、指引、完成三种状态。
地图支持平移、点选、放大、缩小、“查看全层”和“查看当前路线”。
用户从地图设为起点后要得到反馈，并被引导继续选择目的地。
起点、终点、当前路段、中央安检和换层设施都要能辨认。
默认视口让关键标记可见，文字和操作控件不能遮挡标记。

把路线拆成步行、安检、换层、到达等人工确认步骤。
显示当前与下一步，并提供“上一步”“已到达/已通过”“查看全程步骤”。
切换查看其他楼层或路段只改变地图视图，不推进步骤。
适配手机、大字体与宽屏，主要确认按钮固定可见并避让系统区域。

若已按本页设备准备方式创建并连接云手机或模拟器，
请实际操作含安检路线和跨层路线，记录界面与操作结果。
若设备尚未连接，只做代码与逻辑检查，并明确写“设备未测”，
不要模拟用户位置，也不要声称步骤在设备上已通过。
~~~

**完成标志：** 关键地图标记可见；人工确认才能推进，查看地图不会误推进；路线可完成或回退，主要按钮在测试窗口内可操作。

### 7. 补齐双语、状态与异常

**目标：** 让修改路线、返回和重启后的行为一致，文案可切换。

**复制给 AI：**

~~~text
请为当前工程的所有用户可见文案补齐中英双语。
在本机保存语言与最多六个最近目的地；指引进度仅保留在当前会话。
新行程仍从空起终点开始。

编辑起点或终点先改草稿：取消编辑保留原路线和步骤进度；
确认编辑才重新规划、回到预览并将步骤归零。
交换起终点和修改偏好也重新规划并归零。
补齐起终点相同、找不到路、数据缺失、返回、键盘遮挡和地图无可点地点。
请自测中英切换、重启后语言和最近地点、编辑取消与确认、
偏好变化、交换、上一步和完成页；修复发现的问题。
没有实际操作或没有设备的项目要标为未测。
~~~

**完成标志：** 中英文和最近地点符合实际持久化边界，取消与确认编辑状态清楚，异常时用户知道如何重选。

### 8. 编译、安装并做业务验收

**目标：** 用日志、设备操作和截图确认自己的作品，而非照抄现成案例的验收结论。

**复制给 AI：**

~~~text
请对当前独立实现的工程做最终验收，而不是引用现成案例成绩。
先识别 SDK 和构建工具，真实调试构建，报告 BUILD SUCCESSFUL、
HAP 路径和签名状态。若我还没创建设备，请让我先按平台或模拟器流程创建、
启动并连接，再识别目标让我核对，然后安装启动。
若设备或签名阻止安装，保留原始错误，不用编译成功代替设备验收。

安装后逐项操作：新行程空起终点、A101 目的地、西出发门手动起点、
异侧中央安检预览、当前与下一步手动指引、完成页、同侧无需安检、
地铁跨层和电梯偏好、六层地图、双语与最近地点、
编辑取消与确认、交换与返回。
记录每项 PASS、FAIL 或未测及操作证据，并检查运行日志。
只修复能复现的问题，最后说明仍未验证的设备和场景。
~~~

**完成标志：** 有可追溯的构建结果、设备目标和逐项操作记录；失败与未测项明确列出。**本仓库已有的 API 26 编译及 API 24/26 验收只属于现成案例；这八组提示词尚未在空白云端和本地环境完成整轮复现，不能把既有成绩视为新作品的验收通过。**

## 验收与排障

下表可用来核对现成案例，也可作为独立作品的人工验收清单。表后的统计结果只对应仓库现成案例；独立作品需按第 8 步重新留证。

| 场景 | 操作 | 可观察的完成标志 |
| --- | --- | --- |
| 新行程 | 打开首页，进入“去登机口” | 起终点尚未指定；先选目的地，再选手动出发位置。 |
| 安检路线 | 选 A101 → 西出发门 | 预览出现中央安检提示；开始后可见当前与下一步，手动逐项确认。 |
| 同侧路线 | 在同一侧选两处地点 | 预览说明无需经过中央安检，不额外绕行。 |
| 跨层与偏好 | 从 4F 规划到 B2 市区方向站台，选“优先电梯” | 预览列出换层；指引在换层处要求手动确认，步行米数不加垂直边。 |
| 状态回退 | 指引时查看另一楼层、打开全程步骤、上一步 | 查看动作不推进进度；上一步回退。更改偏好或确认编辑后从预览重来。 |
| 编辑与交换 | 编辑起点后取消，再重新编辑确认；交换起终点 | 取消保留原路线及进度；确认或交换重新规划并重置步骤。 |
| 双语与最近 | 切换 English、完成目的地选择后重启 | 中英文文案和地点名切换；语言与最多 6 个最近目的地仍在，本次指引进度不承诺重启保留。 |
| 六层地图 | 首页依次进入 4F、3F、2F、1F、B1、B2 | 能浏览全层、缩放和点击可用地点，点选可参与规划。 |

截至 **2026-10-01**，实际证据为：Python 参考实现 **500 组**起终点配对；ETS 回归 **6/6 套件、2,000 条路线**（500 组 × 4 种偏好）；API 24 中文状态 **21 项**、六层与地图 **14 项**、英文地铁两方向 **6 项**；API 26 手机及宽屏中英文核心流程通过，API 24 手机、宽屏和折叠/展开适配也有截图及流程记录。详情及证据边界见[体验记录](docs/reports/ProductExperience-20261001.md)和[机器可读结果](docs/reports/ProductExperience-20261001.json)。其中 API 23 与真机**未验证**，模拟器通过不等于正式发布验收。

| 现象 | 先检查 | 处理方向 |
| --- | --- | --- |
| 找不到 SDK、Node、Java 或构建工具 | 当前环境是否已提供对应工具；AI 报告的路径能否实际访问 | 按具体缺项配置本地工具链或检查云端环境，再重新编译；不要照搬其他机器的路径。 |
| 构建成功但未找到 HAP | AI 是否报告实际工程根目录、构建日志和产物路径 | 让 AI 在当前工程目录定位生成的 HAP；只有日志和文件均确认才进入安装。 |
| 设备不可见或安装失败 | 云手机/模拟器是否运行且已连接；所选目标和签名状态 | 重新识别设备，保留原始安装错误；需要签名时按设备要求配置，不把其它模拟器的成功当作当前设备通过。 |
| 页面打开但路线为空 | 是否已依次选目的地与起点；两点是否相同 | 重选两个不同的公开地点，再查看路线预览。 |
| 截图或搜索与本页不一致 | 模拟器 API、窗口宽度、语言与字号 | 以 11 张[系统原始截图](docs/images/product-20261001/phone/README.md)和体验记录的条件对照；示例数据及 UI 可能随版本变化。 |

碰到具体问题时，可把日志和操作交给 AI 逐项诊断，而不是预设某一台机器的路径：

~~~text
请根据当前工程和这次实际失败的构建日志、安装错误或页面现象，
先复现并定位原因，再给出最小修复。
区分环境缺失、工程编译、设备连接与签名、业务逻辑问题。
修复后重跑失败步骤，报告实际命令、结果与仍未验证的部分。
不要用现成案例的旧测试记录替代我的独立作品验收，
也不要调用当前工作区并不存在的测试脚本。
~~~
